# tghunter — парсер Telegram-каналов для хантинга блогеров

Инструмент для системного поиска телеграм-каналов финансовой и крипто-тематики
под партнёрские заходы. Находит каналы пятью методами, собирает метрики,
отсекает мусор, скорит по приоритету и выгружает готовый лонглист с контактами.

Работает как CLI и как ежедневный cron-конвейер: новые каналы каждый день.

**Инструмент строго read-only.** Он не вступает в каналы, не пишет сообщения и
не парсит участников — только чтение публичных данных.

> **В репозитории два сервиса.** Второй — `crmai`: ИИ-анализ переписок с
> партнёрами (Wazzup → LLM → amoCRM): авто-статусы сделок примечанием в amo,
> контроль качества исходящих и дайджест руководителю. Документация:
> [README-crmai.md](README-crmai.md). Сервисы независимы, зависимости ставятся
> отдельно (`requirements.txt` и `requirements-crmai.txt`), `.env` общий.

## Быстрый старт

```bash
git clone <repo> && cd tghunter
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env     # заполнить TG_API_ID и TG_API_HASH
python -m tghunter login # один раз: создать сессию Telegram

# положить эталонные каналы (наши топ-партнёры) в config/seed_channels.txt
python -m tghunter run --stream crypto_core
python -m tghunter export --stream crypto_core --new-only
```

Требуется Python 3.11+.

## Создание сессии Telegram

Bot API не умеет ни глобальный поиск, ни чтение чужих каналов, поэтому
используется MTProto через Telethon с **юзер-сессией**.

1. Зайдите на https://my.telegram.org → **API development tools** и получите
   `api_id` и `api_hash`. Впишите их в `.env`.
2. Запустите `python -m tghunter login`. Telethon спросит номер телефона, код
   из Telegram и пароль 2FA, если он включён.
3. Появится файл `sessions/hunter.session` — он в `.gitignore`.

> **Используйте отдельный аккаунт.** Не личный и не основной корпоративный:
> при нарушении лимитов Telegram аккаунт может получить ограничения.
> Файл сессии равносилен паролю от аккаунта — права `600`, не коммитить,
> не копировать между машинами.

## Команды

| Команда | Что делает |
|---|---|
| `login` | Создать / проверить сессию Telethon (один раз при установке) |
| `search "запрос"` | **Свободный поиск по всему Telegram** — ввели фразу, получили ранжированный список |
| `run --stream X` | Прогон одного пресета |
| `run --all` | Прогон всех активных пресетов — режим cron |
| `enrich file.csv` | Обогатить метриками готовый список каналов |
| `import-existing file.csv` | Импорт базы CRM, чтобы не предлагать отработанное |
| `export --stream X` | CSV-выгрузка из базы |
| `rescan` | Обновить метрики каналов старше 30 дней |
| `stats` | Сводка базы |

Общие флаги: `--db PATH`, `--config-dir PATH`, `-v` (подробный лог).

### Потрогать без Telegram: демо-режим

Флаг `--demo` подменяет Telegram встроенным корпусом из 25 вымышленных каналов.
Сеть не используется, сессия и Telethon не нужны — но скоринг, фильтры, дедуп,
база и CSV работают настоящие. Удобно, чтобы освоиться до боевого прогона.

```bash
git clone <repo> && cd tghunter
pip install PyYAML                     # для демо больше ничего не нужно
python -m tghunter --demo search "трейдинг"
python -m tghunter --demo search "фьючерсы" --expand
python -m tghunter --demo run --stream crypto_core
python -m tghunter --demo --db demo.db search "инвестиции" && python -m tghunter --db demo.db stats
```

Каналы в корпусе подобраны так, чтобы задеть каждое правило: монетизированные
и чистые, живые и заброшенные, памперы под стоп-фильтр, каналы без контакта,
русские, англоязычные и тюркоязычные.

### Свободный поиск

Когда нужно не по пресету, а по конкретной фразе:

```bash
python -m tghunter search "трейдинг"
python -m tghunter search "трейдинг, скальпинг, фьючерсы"   # несколько запросов сразу
python -m tghunter search                                    # спросит запрос интерактивно
```

В терминал печатается ранжированная выдача, в `exports/YYYY-MM-DD/` ложится CSV:

```
score  канал                       подпис.    ER% коммент  контакт        вердикт
   75  @futures_desk_demo            18400   12.8      да  @adv_one       в выгрузку
   65  @altcoin_notes_demo           11200   10.5      да  —              в выгрузку
    5  @dead_signals_demo            24000    1.2       —  —              отсев: er 1.25 < 3.0
```

Полезные флаги:

| Флаг | Зачем |
|---|---|
| `--expand` | Дотянуть выдачу нативными рекомендациями Telegram к найденным каналам |
| `--loose` | Не отсекать по ER и живости — показать всё, что нашлось |
| `--lang ru,uk` | Ограничить язык (по умолчанию любой) |
| `--min-subs / --max-subs` | Границы по подписчикам (по умолчанию 1K–1M) |
| `--top 60` | Сколько строк печатать в терминал |
| `--max-channels 50` | Лимит новых каналов за поиск |

Каналы, уже лежащие в базе, показываются с пометкой «уже в базе» и **не стоят
ни одного запроса к API** — метрики берутся из хранилища.

> **Про «весь Telegram».** Глобальный поиск Telegram (`contacts.Search`) — не
> полный индекс: на один запрос отдаётся ограниченная выдача, отсортированная
> самим Telegram. Поэтому охват набирается не длиной одного запроса, а их
> количеством и флагом `--expand`, который тянет lookalike к уже найденному.
> Синонимы и смежные формулировки дают заметно больше, чем одна фраза.

### Примеры

```bash
# Ежедневный конвейер: все пресеты + обновление старых метрик
python -m tghunter run --all --rescan

# Один пресет, лимит 50 новых каналов, без автовыгрузки
python -m tghunter run --stream neighbors --max-channels 50 --no-export

# Лонглист из внешнего источника (TGStat и аналоги)
python -m tghunter enrich longlist.csv --stream crypto_core --export

# Импорт текущей базы CRM для дедупа (нужна колонка username или ссылка)
python -m tghunter import-existing crm_export.csv

# Выгрузка топа за последнюю неделю
python -m tghunter export --stream crypto_core --new-only --min-score 50 --days 7

# Выгрузка + создание сделок в amoCRM
python -m tghunter export --stream neighbors --new-only --amo
```

Коды возврата: `0` — успех, `1` — ошибка конфигурации/подключения,
`2` — прогон остановлен по лимитам Telegram, `130` — прервано пользователем.

## Как это работает

### Методы поиска

Каждый метод включается и выключается в `config/streams.yaml` полем `methods`.

1. **`keywords`** — глобальный поиск Telegram (`contacts.Search`) по словарю
   ключевых слов пресета. Из выдачи берутся только публичные каналы.
2. **`similar`** — нативные рекомендации Telegram
   (`channels.GetChannelRecommendations`) к каждому эталонному каналу из
   `config/seed_channels.txt`. **Главный метод**: lookalike от тех, кто уже
   конвертит. Канал, найденный этим методом, получает +25 к score.
3. **`mentions`** — граф упоминаний: обход последних N постов уже найденных
   каналов, извлечение форвардов, `t.me`-ссылок и `@упоминаний`. Глубина
   задаётся `mention_depth` (по умолчанию 1 уровень от seed-каналов).
4. **`folders`** — разбор папок-подборок `t.me/addlist/*`; список ссылок
   лежит в `config/addlists.txt`.
5. **Ручной ввод** — команда `enrich` для лонглистов из внешних источников.

Между методами инструмент делает паузу 30–60 секунд.

### Конвейер

```
методы поиска → кандидаты → дедуп по базе → сбор метрик → скоринг
              → фильтры → SQLite → CSV / Sheets / amoCRM
```

Дедуп срабатывает **до** обращения к API: канал, уже известный базе, не стоит
ни одного запроса к Telegram. Повторная находка обновляет метрики и не
создаёт дубль; уже выгруженный канал не возвращается в «новые».

## Пресеты стримов

Файл `config/streams.yaml`. Блок `defaults` наследуется всеми пресетами,
любое поле переопределяется в самом пресете.

| Пресет | Что ищет | Подписчики | Режим |
|---|---|---|---|
| `neighbors` | Только similar от наших топ-партнёров | 3–50K | обычный |
| `crypto_core` | Трейдинг, криптовалюта, фьючерсы, альткоины | 3–50K | обычный |
| `invest_tradfi` | Инвестиции, акции, дивиденды, фондовый рынок | 3–50K | обычный |
| `fin_literacy` | Финансовая грамотность, личные финансы | 1–15K | нано-конвейер |
| `signals` | Сигналы, копитрейдинг — усиленный стоп-фильтр | 1–50K | отдельный файл |
| `regional` | Казахский, узбекский, азербайджанский | 1–100K | только лонглист |

### Добавить свой пресет

Допишите блок в `streams`, перечитывать код не нужно:

```yaml
  - name: my_stream
    enabled: true
    description: "Что это за стрим"
    methods: [keywords, similar]
    min_subscribers: 2000
    max_subscribers: 30000
    languages: [ru]
    keywords:
      - моё ключевое слово
    extra_blacklist:          # поверх config/blacklist_markers.txt
      - дополнительный стоп-маркер
```

Затем `python -m tghunter run --stream my_stream`.

Режим `mode: longlist` отключает пороги ER и живости — канал попадает в
выгрузку для ручного разбора, стоп-маркеры и границы по подписчикам при этом
продолжают работать.

### Прочие конфиги

| Файл | Назначение |
|---|---|
| `config/seed_channels.txt` | Эталонные каналы для `similar` |
| `config/addlists.txt` | Ссылки `t.me/addlist/*` для `folders` |
| `config/blacklist_markers.txt` | Стоп-слова, редактируется без правки кода |

## Метрики и скоринг

### Что собирается для каждого канала

- **Базовое**: username, title, описание, подписчики, дата последнего поста, ссылка.
- **ER**: среднее просмотров последних 10 постов / подписчики, в процентах.
  Рядом пишется медиана просмотров — она устойчива к вирусным выбросам.
  Посты старше 60 дней в расчёт не берутся.
- **Живость**: дней с последнего поста, постов за последние 30 дней.
- **Комьюнити**: среднее реакций на пост, включены ли комментарии
  (наличие linked discussion group).
- **Язык**: `ru` / `uk` / `en` / `turkic` (kz-uz-az) / `other`.
- **Монетизация**: продаёт ли канал рекламу — `#реклама`, `#промо`, `erid`,
  «реклама.», ссылки на биржи и обменники с `utm`/реф-параметрами.
  Канал, уже продающий рекламу, — приоритетная цель.
- **Контакт**: `@username` админа из описания («по рекламе: @...»). Если
  контакта нет, канал помечается `no_contact` и уходит в отдельный файл выгрузки.
- **Стоп-маркеры**: совпадение помечает канал `blacklist_hit` с указанием
  маркера. Такой канал исключается из выгрузки, но **остаётся в базе**, чтобы
  не проверять его повторно.

### Фильтры (пороги в пресете)

- Подписчики в диапазоне пресета.
- `ER >= 3%` **ИЛИ** (комментарии включены **И** среднее реакций `>= 5`).
- Последний пост не старше 14 дней и `>= 4` постов за 30 дней.
- Язык из списка пресета.
- Нет `blacklist_hit`.

### Скоринг (0–100)

| Баллы | За что |
|---|---|
| +30 | Монетизация: канал продаёт рекламу |
| +25 | Найден через `similar` к эталонному каналу |
| +20 | ER выше 7% |
| +10 | Есть контакт в описании |
| +10 | Комментарии включены и живые (реакции >= 5) |
| +5 | Частота 8+ постов в месяц |

Score и его разбивка (`monetized+30|similar+25|...`) пишутся в выгрузку;
сортировка — по убыванию score.

### Добавить свою метрику

Слой метрик — цепочка провайдеров `ChannelSnapshot -> dict`. Новый модуль
(например, LLM-классификация тематики) добавляется одной функцией, остальной
код менять не нужно:

```python
from tghunter.metrics import register_provider

def topic_classifier(snapshot, ctx):
    return {"topic": classify(snapshot.about), "quality": 0.9}

register_provider("topic", topic_classifier)
```

Ключи из возвращённого словаря автоматически попадают в `metrics_json` базы;
чтобы вывести их в CSV, добавьте колонку в `EXPORT_COLUMNS`.

## Выгрузки

### CSV (всегда)

```bash
python -m tghunter export --stream crypto_core --new-only
```

Файл `exports/YYYY-MM-DD/crypto_core_new.csv`, разделитель `;`, кодировка
`utf-8-sig` — Excel открывает кириллицу без плясок. Каналы без контакта
выгружаются отдельным файлом `*_no_contact.csv`.

Колонки: username, ссылка, title, подписчики, ER, медиана просмотров, среднее
просмотров, дней с последнего поста, постов за 30 дней, среднее реакций,
комментарии, язык, монетизация, маркеры монетизации, контакт, score, разбивка
score, метод, источник, стрим, статус, даты находки и проверки.

### Ежедневный конвейер

```bash
python -m tghunter run --all --rescan
```

Прогоняет все активные пресеты, складывает CSV новых каналов за день в
`exports/YYYY-MM-DD/` и, если заданы `TG_BOT_TOKEN` и `TG_SUMMARY_CHAT_ID`,
шлёт в Telegram короткую сводку: сколько найдено новых и топ-5 по score.

Постановка в расписание — systemd-таймер или cron, см. `deploy/install.md`.
Оба варианта запрещают параллельные прогоны: `flock` для cron, oneshot-юнит
для systemd.

### Google Sheets (опционально)

```bash
pip install gspread google-auth
# SHEETS_CREDENTIALS_FILE и SHEETS_SPREADSHEET_ID в .env
python -m tghunter export --stream crypto_core --new-only --sheets
```

### amoCRM (опционально)

```bash
# AMO_BASE_URL, AMO_ACCESS_TOKEN, AMO_PIPELINE_ID, AMO_STATUS_ID и AMO_FIELD_* в .env
python -m tghunter export --stream neighbors --new-only --amo
```

Создаёт сделки в воронке хантинга со статусом «Новый»; поля — название канала,
ссылка, подписчики, ER, стрим, score. Дедуп на стороне amo по ссылке канала:
перед созданием ищется сделка с такой же ссылкой.

## Безопасность аккаунта

Раздел, который лучше не править без причины.

| Ограничение | Как реализовано |
|---|---|
| Отдельный аккаунт | Сессия лежит локально, `api_id`/`api_hash` только из `.env` |
| Rate limit | Не чаще одного запроса в 2–3 секунды со случайным джиттером |
| FloodWait | Сон на указанное время +10%, запись в лог |
| Серия FloodWait | Два подряд — прогон останавливается, в сводку пишется «остановлен по лимитам» |
| Долгий FloodWait | Пауза от часа не отсиживается — прогон останавливается сразу |
| Лимит за прогон | `MAX_CHANNELS_PER_RUN`, по умолчанию 200 новых каналов |
| Пауза между методами | 30–60 секунд |
| Только чтение | Никаких вступлений, сообщений и парсинга участников |
| Один процесс | Без параллельных сессий: `flock` в cron, oneshot-юнит в systemd |
| Секреты | Только `.env`; `*.session` и `.env` в `.gitignore` |

Настройки лимитов — `RATE_MIN_INTERVAL`, `RATE_MAX_INTERVAL`,
`MAX_CHANNELS_PER_RUN`, `METHOD_PAUSE_MIN`, `METHOD_PAUSE_MAX`,
`FLOODWAIT_ABORT_STREAK` в `.env`.

## Разработка

```bash
pip install pytest
python -m pytest tests/ -q
```

Тесты не ходят в сеть: Telethon подменяется фейковым шлюзом (`tests/conftest.py`),
поэтому весь конвейер — поиск, метрики, скоринг, фильтры, дедуп, выгрузки —
проверяется локально.

### Структура

```
tghunter/
├── cli.py            CLI и команды
├── search.py         свободный поиск по запросу
├── demo.py           встроенный корпус каналов для --demo
├── config.py         .env, streams.yaml, seed-файлы
├── models.py         Candidate / Post / ChannelSnapshot
├── tg.py             единственный модуль, знающий про Telethon
├── ratelimit.py      троттлинг, FloodWait, лимит каналов за прогон
├── discovery/        пять методов поиска
├── metrics.py        цепочка провайдеров ChannelSnapshot -> dict
├── language.py       эвристика языка
├── textscan.py       контакты, маркеры монетизации, стоп-слова
├── scoring.py        score 0-100 и разбивка
├── filters.py        пороги пресета
├── db.py             SQLite, дедуп, история обходов
├── pipeline.py       конвейер прогона
└── exporters/        CSV, Google Sheets, amoCRM, сводка в Telegram

crmai/                ИИ-анализ диалогов — см. README-crmai.md
prompts/              шаблоны промптов и контекст компании для crmai
```

Весь код, кроме `tg.py`, работает с нормализованными структурами из
`models.py` — это и позволяет тестировать конвейер без сети.

### Вне скоупа

Парсинг участников каналов, авторассылка и заходы, обход приватных каналов,
интеграции TGStat/Telemetr (появятся отдельным модулем при платном доступе),
анализ контента LLM — под него заложен интерфейс провайдеров метрик.
